# Алгоритм оптимизации

Сервис решает задачу: разделить область съёмки между бортами разнородного парка и построить каждому борту индивидуальное полётное задание так, чтобы минимизировать выбранный критерий:

- **T_max** — время выполнения всех работ (момент, когда последний борт закончил последний вылет, включая смену АКБ);
- **ΣT** — суммарный налёт всех бортов.

Критерии задаются весом `w ∈ [0, 1]`: целевая функция `J = w·T_max/T_ref + (1 − w)·ΣT/ΣT_ref`, где `T_ref`, `ΣT_ref` — значения сбалансированного по времени плана. `w = 1` — только время работ, `w = 0` — только налёт. Режим «фронт Парето» решает задачу для набора весов и оставляет недоминируемые планы.

Код ядра — `backend/planner/`. Ниже — этапы в порядке выполнения, с модулем и первоисточником.

## 1. Геометрия и рабочая область — `geo.py`, `planner.py`

Все координаты переводятся из WGS84 в локальную азимутальную равнопромежуточную проекцию с центром в районе работ (pyproj), расчёты ведутся в метрах.

Рабочая область: `A = (область съёмки ∩ разрешённая зона) − buffer(NFZ, запас)`. Запас по умолчанию 30 м.

## 2. Параметры съёмки — `sensors.py`

Для каждого борта выбирается нагрузка, подходящая под тип съёмки (`fleet.yaml`), и считаются высота, ширина полосы, шаг галсов и скорость.

| Тип съёмки | Формулы | Источник |
|---|---|---|
| RGB, мультиспектр, ИК | `H = GSD·F·imW / Sw`; полоса `= imW·GSD`; шаг галсов `= полоса·(1 − поперечное перекрытие)`; базис `= imH·GSD·(1 − продольное)`; интервал съёмки `= базис / V` | Pix4D: GSD, перекрытия |
| LiDAR | полоса `= 2H·tan(FOV/2)`; плотность `≈ PRF / (V·полоса)`; скорость снижается до обеспечения заданной плотности | USGS Lidar Base Specification |
| Геофизика (магнитометр, гамма) | малая высота (30 м), шаг галсов 50 м, секущие маршруты с шагом ×10, скорость ≤ 8 м/с, огибание рельефа | UAV Magnetic Survey Guidelines (2022); руководство Геоскан 401, с. 102 |

Высота ограничивается минимальной безопасной высотой борта (201 — 100 м, 401 — 25 м), потолком разрешённого объёма и дальностью сканера. Если интервал срабатывания камеры не успевает, мультиротор снижает скорость. Если ветер сильнее скорости съёмки, скорость поднимается до `W + 2 м/с` в пределах ТТХ. Борт исключается с объяснением, если съёмка невозможна (ветер выше паспортного, нет нужной нагрузки, скорость не выше ветра).

## 3. Ветер — `wind.py`

Путевая скорость вдоль направления χ при воздушной скорости V_a и ветре W (треугольник скоростей):

`V_g = W_along + √(V_a² − W_cross²)`, линия пути недостижима при `|W_cross| ≥ V_a`.

Ветер влияет на время каждого участка, на выбор направления галсов и на бюджет мультиротора.

## 4. Бюджет вылета — `energy.py`

`бюджет = паспортная продолжительность × (1 − резерв)`; резерв по умолчанию 20 %. Для мультиротора — поправка на ветер `× (1 − 0,3·(W/W_max)²)`: чем сильнее ветер, тем больше потребная мощность (Dorling et al., 2017; Thibbotuwawa et al., 2019). Коэффициент 0,3 — допущение.

## 5. Галсы и их порядок — `coverage.py`, `mission.py`

1. **Направление.** Кандидаты — направления рёбер выпуклой оболочки (Huang, 2001: оптимум по числу разворотов лежит на них) и сетка через 10°. Для каждого считается время съёмки с учётом ветра и разворотов, выбирается минимальное (Coombes et al., 2017).
2. **Галсы.** Параллельные линии с шагом «шаг галсов», первая — на половине шага от края. Невыпуклость и дыры (NFZ) дают несколько отрезков на линии.
3. **Клеточная декомпозиция.** Отрезки соседних линий, переходящие друг в друга один к одному, объединяются в ячейки boustrophedon (Choset, 2000). Внутри ячейки — змейка, ячейки обходятся жадно: следующая — ближайшая к концу предыдущей.

## 6. Развороты — `dubins.py`, `turns.py`

- **Самолёт (Геоскан 201).** Кратчайший путь Дубинса между концом галса и началом следующего с радиусом `R = V²/(g·tan φ)`, φ = 30° (Dubins, 1957; формулы Shkel & Lumelsky, 2001). При шаге галсов меньше 2R получается петля — «разворот с выходом на ЛЗП» из руководства Геоскан 201. Петля выходит за конец галса, поэтому у NFZ и у границы разрешённой зоны самолёту оставляется запас на вынос петли; эти полосы передаются ближайшему мультиротору, который до них долетает.
- **Мультиротор.** Остановка, поворот на месте, разгон: потеря `V/a`, a = 2,5 м/с² (допущение).

## 7. Обход запретных зон — `avoid.py`

Все перелёты (к области, между ячейками, возврат, уход на площадку) строятся по графу видимости (Lozano-Pérez & Wesley, 1979): узлы — вершины раздутых NFZ и сдвинутой внутрь границы разрешённой зоны, рёбра — взаимно видимые пары, кратчайший путь — Дейкстра. Проверки видимости векторизованы (shapely 2).

## 8. Нарезка на вылеты — `mission.py`

Принцип route-first / cluster-second (Beasley, 1983): маршрут обхода всех галсов режется на вылеты так, чтобы `взлёт + подход + галсы + возврат + посадка ≤ бюджет`. Галс, который не помещается целиком, делится бисекцией. Вылеты борта идут последовательно, между ними — смена АКБ (201 — 20 мин, мультироторы — 10 мин, допущения).

## 9. Распределение по парку — `partition.py`, `grid_partition.py`, `planner.py`

1. **Производительность борта:** `скорость · шаг галсов · доля времени в воздухе` (с учётом взлёта, посадки и смены АКБ). Стартовые доли площади пропорциональны производительности (Maza & Ollero, 2007).
2. **Разбиение полосами.** Область режется линиями, параллельными галсам, на полосы с заданными долями площади (бисекция по площади). Полосы сопоставляются бортам по положению их баз. Каждая полоса содержит галсы полной длины — минимум разворотов.
3. **Разбиение с учётом дальности** — если полоса оказалась вне досягаемости борта. Область покрывается сеткой, выровненной по галсам; каждый борт растит свой участок от базы, забирая соседние клетки в пределах радиуса действия `r = ½·(бюджет − взлёт − посадка)·(V − W)·0,85`, ограниченного дальностью радиоканала (по мотивам DARP, Kapoutsis et al., 2017). Короткодействующие мультироторы остаются у баз, дальние участки уходят самолётам.
4. **Балансировка по времени (w = 1).** Доли корректируются по фактическому времени окончания работ: `f_i ← f_i·(T_mean/T_i)^0.8`, до выравнивания в пределах 2 %. Мультистарт: доли по производительности и равные доли.
5. **Локальный поиск (w < 1).** Из лучшего решения и из стартов «вся работа одному борту» — перенос доли от борта i к борту j с убывающим шагом, пока J уменьшается; борт с долей < 2 % выводится из плана.

## 10. Проверка плана — `planner.py`

- ни один участок не пересекает NFZ; перелёты не выходят из разрешённой зоны;
- каждый вылет укладывается в бюджет;
- дальность от базы не превышает дальность радиоканала;
- для каждой точки вылета (шаг 400 м) — время ухода на ближайшую ВПП или резервную площадку с обходом зон; если оно больше резерва заряда — предупреждение;
- покрытие: объединение полос съёмки ∩ рабочая область.

## 11. Высоты и рельеф — `terrain.py`, `planner.py`

Рельеф — Copernicus DEM GLO-30 (DSM, 30 м, высоты над геоидом EGM2008), тайлы из открытого бакета AWS без ключа, кэш в `data/dem/`.

- Мультиротор: огибание рельефа на галсах (точки через 100 м, для геофизики — через 50 м), на перелётах — постоянный уровень `max(рельеф на участке) + высота`.
- Самолёт: постоянный эшелон на вылет `max(рельеф по вылету, высота точки старта) + высота` — не ниже точки старта (руководство Геоскан 201, с. 12).

## 12. Результаты

Сравнение с базовыми подходами и масштабируемость — [benchmark.md](benchmark.md). Коротко:
- по критерию «время работ» план в 1,2–2,2 раза быстрее, чем работа одного лучшего борта;
- равное деление области без учёта ТТХ на смешанном парке медленнее в 2,5–2,9 раза, на однородном парке и на 110 км² — на 1–4 %;
- по критерию «налёт» план не хуже лучшего одиночного борта, а на 110 км² лучше (779 против 792 мин) при в 2 раза меньшем времени работ;
- области до 64 км² парком до 8 бортов считаются за 0,05–4,5 с.
